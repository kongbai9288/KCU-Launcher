# 离线账号迁移契约

> 供 **KCU Migrator** 等外部工具读写。
> 维护者：yuanbao　最后更新：2026-10-24　v0.53.0

---

## 1. 文件位置

与 `manifest.json` 同级：

```
/sdcard/KCU/accounts.json        （根为 KCU 时）
/sdcard/FCL/accounts.json        （迁移用户根选了 FCL 时）
```

**实际根以 `manifest.json` 的 `root` 字段为准**，不要硬编码。

---

## 2. 格式

```json
{
  "schemaVersion": 1,
  "status": "exported",
  "exportedAt": 1761320000000,
  "accounts": [
    { "username": "Steve", "uuid": "f84c6a79-0a4e-45e0-879b-cd49ebd4c4e2" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `schemaVersion` | 当前 `1` |
| `status` | `exported` = 启动器导出的快照；`pending` = **请启动器导入** |
| `exportedAt` | 毫秒时间戳 |
| `accounts[].username` | 离线账号名 |
| `accounts[].uuid` | 离线 UUID（带连字符的标准形式） |

---

## 3. 为什么只有离线账号

**正版（微软）和第三方（authlib-injector）账号不导出，也不导入。**

原因：它们的存储内容包含**登录凭据**（access token / refresh token 等）。
公共目录可被设备上任意应用读取，把凭据写进去等同于明文泄露。

离线账号只有 **名称 + UUID**，不含任何凭据，可以安全迁移。

导入端同样只接受 `username` / `uuid` 两项；即使外部写入了别的字段，也会被忽略。

---

## 4. 迁移流程

### 4.1 导出（启动器 → 外部工具）

启动器在**每次进入主界面前**重写该文件：

1. 先执行导入（见 4.2）
2. 再写出当前全部离线账号快照，`status = "exported"`

外部工具直接读即可，**不需要任何触发操作**。

⚠ 文件反映的是**上一次启动结束时**的状态。若用户在本次会话中新增了离线账号，
要等下次启动才会出现在文件里。

### 4.2 导入（外部工具 → 启动器）

外部工具把文件写成：

```json
{ "schemaVersion": 1, "status": "pending", "accounts": [ ... ] }
```

启动器下次启动时：

1. 读取 `status`，**只有等于 `pending` 才导入**（`exported` 直接跳过 → 不会重复导入）
2. 逐条处理：名称合法（3-16 位字母数字下划线）且本地无同名账号 → 创建
3. **已有同名账号的跳过**，不覆盖
4. 导入完成后把文件重写为 `status = "exported"`

**因此导入是一次性的**：同一份 `pending` 文件不会被导入两遍。

---

## 5. UUID 为什么必须沿用

离线身份由 **UUID** 决定 —— MC 的世界数据（背包、进度、末影箱）按 UUID 归属。

若迁移时重新按名字推导 UUID（`UUID.nameUUIDFromBytes("OfflinePlayer:" + name)`），
虽然对**同名**账号结果相同，但对改名/大小写不同的情形会变成另一个身份，
玩家会发现存档"不是自己的"。

所以：
- 有 UUID → **直接用**
- 没 UUID → 才按名字推导兜底

## 6. 已知限制

| # | 限制 |
|---|---|
| 1 | **不迁移皮肤**。离线皮肤的存储可能含本地文件路径，跨设备无意义 |
| 2 | 导入发生在启动器**启动阶段**（`SplashActivity`），不是实时监听文件变化 |
| 3 | 导入在 IO 线程执行，账号列表变更未做主线程切换（未实机验证是否引发绑定异常） |
| 4 | 名称不合法（含非法字符或长度不符）的条目被**静默跳过**，无日志 |

## 7. 未验证

**本契约从未在真机上跑过。** 具体未验证项：

- `accounts.json` 是否真的生成
- 放一份 `status: "pending"` 的文件后，账号是否被导入
- 导入后文件是否被正确改写为 `exported`
- 跨设备迁移 UUID 是否真的保住了存档归属
