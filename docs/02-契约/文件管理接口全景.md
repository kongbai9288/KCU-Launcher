# 文件管理接口全景

面向两件事：一，改文件管理时不漏掉某个入口；二，开源时不漏掉某个文件。

**标记规则**：条目末尾带 `<!-- ✓ -->` 表示已核对到具体代码行，或用等价程序实测过；没有该标记的属于推断或未验证，**不要当作既成事实**。文末有完整的「未验证清单」。

---

## 零、一句话结论

文件管理不是一个页面，而是**一套「内置浏览器 + 系统选择器 + 对外 DocumentsProvider」的三层结构**：

```
调用方 ──(FileBrowserLauncher)──> FileBrowserActivity ──(结果)──> SelectedFile
                                        │
                                        └──(长按/管理菜单)──> FileOperator + FileClipboard

游戏内点目录链接 ──> OpenFolderDialog（内嵌列表 + 系统选择器导入）

其它应用（MT 管理器等）──(SAF)──> FolderProvider ──> 本应用私有目录
```

**它之所以"不像正常软件"，根因有三条**（详见 §11）：

1. 选完文件没有结果 —— 承载回调的那个对象在 Activity 重建后是新的。**（P0）**
2. 每次进目录都重建列表 —— 滚动位置丢失、大目录主线程卡顿。**（P0）**
3. 选文件要点两下（点条目选中 → 点确认），且确认按钮在最右侧竖排里。**（P1）**

## 二、三种模式 × 两种选择方式

`LibMode`（三选一）与 `SelectionMode`（二选一）是**两个独立维度**，共 6 种组合，但实际有意义的只有 4 种。

### 2.1 LibMode

| 值 | 顶部显示 | 列表内容 | 点目录 | 点文件 |
|---|---|---|---|---|
| `FILE_BROWSER`（默认） | Browse File | 目录 + 文件（按后缀过滤） | 进入 | 加入/移出选中集 |
| `FILE_CHOOSER` | Pick File | 目录 + 文件（按后缀过滤） | 进入 | 加入/移出选中集 |
| `FOLDER_CHOOSER` | Pick Folder | **只列目录** | 进入并选中 | 不响应 |

`<!-- ✓ -->`（`FileOperator.getFileList` 第 49–57 行：`FOLDER_CHOOSER` 时只把 `isDirectory()` 的条目加入 `list`；适配器第 136–141 行：点目录一律 `onEnterDir`，点文件仅在非 `FOLDER_CHOOSER` 时 `onSelect`）

### 2.2 SelectionMode

| 值 | 顶部显示 | 点文件行为 |
|---|---|---|
| `SINGLE_SELECTION`（默认） | Single Selection | 清空旧选中，只留这一个 |
| `MULTIPLE_SELECTION` | Multiple Selection | 追加或移出 |

`<!-- ✓ -->`（`FileBrowserActivity.onSelect` 第 231–243 行）

### 2.3 ★ 组合里的坑

- **`FILE_BROWSER` + `SINGLE_SELECTION`**：确认按钮在选中为空时也放行（第 305 行：`selectedFiles.isEmpty() && libMode != FILE_BROWSER` 才提示）。所以浏览模式点确认会返回一个**空列表**。调用方若写 `files.get(0)` 会崩。<!-- ✓ -->
- **`FOLDER_CHOOSER` 下进入目录即选中**：`refreshList` 第 218–221 行把当前路径写进选中集。所以"选文件夹"实际是"进到哪就选哪"，确认返回当前目录。**没有取消选中的入口**（点目录是进入，不会取消）。<!-- ✓ -->
- **单选选择器隐藏了批量菜单**：`showManageMenu` 第 384–390 行，`FILE_CHOOSER` + `SINGLE_SELECTION` 时不显示"批量操作"，避免全选后破坏单选约定。<!-- ✓ -->

## 五、结果契约：SelectedFile

`FileBrowser.getSelectedFiles(Intent)` 返回 `List<SelectedFile>`，或 `null`（data 为 null）。

```kotlin
class SelectedFile(val uri: Uri) {
    val isContent: Boolean            // scheme == "content"
    val file: File?                   // 本地路径；content 时为 null
    val path: String                  // uri 的原始字符串
    fun fileName(context): String     // 显示名（content 走 OpenableColumns.DISPLAY_NAME）
    fun openInputStream(context): InputStream?
    fun toFile(context, cacheDir): File    // 本地直接返回；content 拷到 cacheDir 再返回
    fun copyTo(context, dest)         // 拷到指定文件
}
```

### 5.1 两种来源

| 来源 | uri 形如 | `file` | 读内容 |
|---|---|---|---|
| 内置浏览器确认 | 本地绝对路径 | 非 null | 直接 |
| 系统选择器（external） | `content://...` | **null** | 必须先 `toFile()` 或 `openInputStream()` |

**content 授权是临时的**，必须立刻读取或拷贝，不能只存 uri 字符串留着以后用。<!-- ✓ -->

### 5.2 调用方标准写法

```kotlin
fileLauncher.launchSingleSelection(null, listOf(".png")) { files ->
    val selected = files?.get(0) ?: return@launchSingleSelection
    val f = selected.toFile(activity, File(KCUPath.CACHE_DIR))
    ...
}
```

`<!-- ✓ -->`（`VersionSettingPage.kt:272-277` 原文如此）

### 5.3 ★ 结果里没有的东西

`SelectedFile` **不含**：文件大小、MIME 类型、父目录、是否为目录（本地情形）。

要不要判断 `file.isDirectory` 由调用方自己做。<!-- ✓ -->

### 7.1 实测：排序行为

用等价 Java 程序实测（样本：目录 `a`、`B`；文件 `Alpha.jar`(5B) `b.jar`(300B) `m.jar`(7B) `zeta.txt`(10B)，修改时间 b>Alpha>m>zeta）：

| 排序方式 | 实测输出 |
|---|---|
| `NAME` | `a` `B` `Alpha.jar` `b.jar` `m.jar` `zeta.txt` |
| `SIZE` | `B` `a` `Alpha.jar` `m.jar` `zeta.txt` `b.jar` |
| `DATE` | `a` `B` `b.jar` `Alpha.jar` `m.jar` `zeta.txt` |
| null | 同 `NAME` |

`<!-- ✓ -->`（实测）

**实测揭示两点**：

1. 实现是**先按所选方式排一遍，再用目录优先比较器稳定排一遍**（`List.sort` 稳定），所以"目录恒在前、组内按所选方式排"成立。<!-- ✓ -->
2. **`DATE` 是倒序（新的在前），`NAME`/`SIZE` 是正序**，三者方向不一致。而且切到 `SIZE`/`DATE` 时目录之间的相对顺序会变（`a B` ↔ `B a`），因为目录也参与长度/时间比较。<!-- ✓ -->

### 7.2 实测：后缀过滤

| 传入后缀 | 命中 |
|---|---|
| `.jar` | `Alpha.jar` `b.jar` `m.jar` |
| **`jar`（漏写点）** | `Alpha.jar` `b.jar` `m.jar` **`notjar`** |

`<!-- ✓ -->`（实测；`endsWith` 是纯后缀匹配，不带点会误命中）

### 7.3 实测：重名与文件名校验

| 输入 | 结果 |
|---|---|
| 已存在 `m.jar` | `m (1).jar` |
| 不存在的 `x.jar` | `x.jar` |
| 隐藏文件 `.nomedia` | `.nomedia`（`dot > 0` 不成立，不拆扩展名） |

`isValidFileName` 实测放行：`..`、`.`、`a:b`、`a?b`、`a*b`；拦截：`a/b`、纯空格。<!-- ✓ -->

> `..` 与 `.` 虽被放行，但随后 `new File(dir, name).exists()` 成立，会被"已存在"拦下，实际造不出来。真正漏掉的是 `:` `?` `*` 这类在 FAT/exFAT 上非法的字符 —— 失败时只弹一句"操作失败"，不说是名字非法。<!-- ✓ -->

## 十一、已确认的问题清单（按严重度）

### P0-1 ★ 选完文件没有结果（回调丢失）

```
调用方 Activity ──启动──> FileBrowserActivity
        │                        （前台停留很久 / 转屏 / 内存回收）
        └─被系统销毁重建─> 新的 KCUActivity
                          └─新的 fileLauncher（currentFileBrowser = null）
                                    │
FileBrowserActivity 选完点确认 ──> 回调发现 currentFileBrowser == null
                                └─什么都不做 ──> 玩家：点了没反应
```

**证据**：`KCUActivity.java:56` 在初始化里 `new FileBrowserLauncher(this)`；`FileBrowserLauncher` 的 `currentFileBrowser` 是实例字段；回调里第一行就判 `currentFileBrowser != null && callback != null`，不成立则静默返回。<!-- ✓ -->

**为什么常见**：浏览大目录（比如 Downloads、mods）时本 Activity 长时间在前台，调用方 Activity 极可能被回收；返回时调用方重建，回调就没了。

**修法方向**：把回调放进可跨重建恢复的地方（如 `ActivityResultRegistry` 之外再挂一层 SavedStateHandle），或在 `FileBrowserActivity` 里直接把结果写进 `setResult` 并让调用方用稳定的 result key 取。**改之前先定方案，别直接动。**

### P0-2 ★ 滚动位置丢失 + 大目录主线程卡顿

`refreshList()` 每次都 `new FileBrowserAdapter(...)` + `listView.setAdapter(adapter)`：

- **列表重建 → 滚动位置回到顶部**。进子目录再返回，位置丢了。
- **`getFileList` 在构造适配器时同步执行**，而 `refreshList` 在主线程调用。
- `getView` 里每个条目还同步调 `FileUtils.lastModified()` 和 `FileUtils.sizeOf()`（两次 IO）。

上千个文件的目录会明显卡顿。<!-- ✓ -->

**修法方向**：列表数据在 IO 线程取、主线程只 setAdapter；复用同一个 adapter 只换数据；用 `RecyclerView` + 记录 `onSaveInstanceState` 的滚动位置。

### P1-1 选文件要点两下

点文件只是"加入选中集"（变灰），必须再点最右侧竖排里的"确认"才返回。正常文件选择器点一下就返回。

### P1-2 结果 uri 用 `Uri.parse(绝对路径)` 生成

```java
selectedFiles.stream().map(Uri::parse)
```

`selectedFiles` 里存的是 `file.getAbsolutePath()`。`Uri.parse` 会按标准 uri 规则切分 `?`（query）和 `#`（fragment），**文件名含 `#` 或 `?` 时路径被截断**，调用方拿到错误的文件。

> 这一条是源码分析 + Android Uri 解析规则推得的，**沙盒里跑不了 Android Uri，未实测**。已列入未验证清单。

**修法方向**：改用 `Uri.fromFile(file)`，或统一走 `FileProvider.getUriForFile`。

### P1-3 `FILE_BROWSER` 点确认返回空列表

第 305 行：只有非浏览模式才校验"未选择"。浏览模式点确认 → 返回空列表 → 调用方 `files.get(0)` 越界。

### P1-4 粘贴到自身子目录会递归

`pasteClipboard` 无父子关系检查。复制 `/sdcard/KCU` 后进入 `/sdcard/KCU/mods` 粘贴 → `FileUtils.copyDirectory` 把目录拷进自己的子目录 → 无限递归直至失败。

### P1-5 分享在 debug 包崩溃

见 §9.2。

### P2 其余

- `manage` 菜单里"粘贴"无条件显示，剪贴板为空时点下去只弹一句提示
- 返回键只能退到 `/sdcard`，不能退到 `initDir` 之外；从私有目录进来会被一路推到 `/sdcard`
- `openExternal` 硬编码 `FCL`
