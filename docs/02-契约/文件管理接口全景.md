# 文件管理接口全景

面向两件事：一，改文件管理时不漏掉某个入口；二，开源时不漏掉某个文件。

本文所有结论均从仓库源码逐条读出。**文末带 `<!-- ✓ -->` 的条目表示已核对到具体代码行**；没有该标记的条目属于推断或未验证，不要当作既成事实。

---

## 零、一句话结论

文件管理不是一个页面，而是**一套"启动器内置浏览器 + 系统选择器 + 对外 DocumentsProvider"的三层结构**：

```
调用方 ──(FileBrowserLauncher)──> FileBrowserActivity ──(结果)──> SelectedFile
                                        │
                                        └──(长按/管理菜单)──> FileOperator + FileClipboard

游戏内点目录链接 ──> OpenFolderDialog（内嵌列表 + 系统选择器导入）

其它应用（MT 管理器等）──(SAF)──> FolderProvider ──> 本应用私有目录
```

## 二、三种模式与两种选择方式

`LibMode`（3 个值）：

| 值 | 含义 | 列表内容 | 点目录 |
|---|---|---|---|
| `FILE_BROWSER` | 纯浏览管理 | 目录 + 文件（按后缀过滤） | 进入 |
| `FILE_CHOOSER` | 选文件 | 目录 + 文件（按后缀过滤） | 进入（不可选） |
| `FOLDER_CHOOSER` | 选文件夹 | **只列目录**，后缀过滤被绕过 | 进入并记为当前选择 |

`SelectionMode`（2 个值）：`SINGLE_SELECTION`（默认）、`MULTIPLE_SELECTION`。

`SortMode`（3 个值）：`NAME`（默认）、`SIZE`、`DATE`（日期为倒序）。排序持久化在 `SharedPreferences` 名为 `launcher`、键 `file_browser_sort_mode`，写用 `apply()`。

<!-- ✓ -->

### 交互规则（易踩）

- 目录恒排在最前，组内按 `SortMode` 排。
- `FOLDER_CHOOSER` 下点文件**无任何反应**（适配器只在 `isFile()` 且非该模式时触发选中）。
- `FOLDER_CHOOSER` 下**不点任何东西直接确认也会返回当前目录** —— 进入目录时就把该目录写进选中集合。
- 后缀过滤只对文件生效，目录一律保留。
- 选中态只影响背景色，选中不会自动确认。

## 三、启动方式（三个口）

### 口 1：`FileBrowserLauncher`（推荐）

宿主 Activity 继承 `KCUActivity` 时，字段 `fileLauncher` 已在 `onCreate` 建好。

```kotlin
// 单文件
fileLauncher.launchSingleSelection(initDir, listOf(".jar")) { files ->
    val f = files?.get(0) ?: return@launchSingleSelection
    val file = f.toFile(context, File(KCUPath.CACHE_DIR))
}
// 单目录（isDirectory = true）
fileLauncher.launchSingleSelection(null, null, true) { files -> ... }
// 多文件
fileLauncher.launchMultiSelection(null, listOf(".zip")) { files -> ... }
```

`initDir` 传 `null` 时落在 `Environment.getExternalStorageDirectory()`。

回调收到 `null` 的情况只有两种：结果是 `RESULT_CANCELED`；或结果是 OK 但 `data` 为 `null`。

**收到空列表是另一回事** —— 结果为 OK、`data` 非空但里面没有 `SELECTED_FILES` 时，得到的是空列表而不是 `null`。调用方判空要两种都覆盖：`files == null || files.isEmpty()`。

`currentFileBrowser` 或它的 `callback` 为 `null` 时，回调**完全不触发**（静默）。



<!-- ✓ -->

### 口 2：`FileBrowser.Builder` + `launcher.launch(config)`

需要自定义标题、初始目录、模式组合时用。`Builder(Context)` 会把默认标题设为 `file_browser_title`。

```java
FileBrowser fb = new FileBrowser.Builder(ctx)
        .setLibMode(LibMode.FILE_CHOOSER)
        .setSelectionMode(SelectionMode.MULTIPLE_SELECTION)
        .setSuffix(List.of(".jar"))
        .setInitDir(dir)
        .setCallback(files -> { ... })
        .create();
fileLauncher.launch(fb);
```

注意 `callback` 字段是 `transient` —— 序列化传给 Activity 后那份没有 callback，Launcher 用的是自己持有的原对象。**不要指望 Activity 侧能回调。**

<!-- ✓ -->

### 口 3：`browse()`（已弃用 / 有坑）

```java
@Deprecated
public void browse(Activity activity, int code, ResultListener.Listener listener)  // 走 ResultListener
public void browse(Activity activity)                                             // 只 startActivity
```

后者**不取结果**，也没有 callback 通路，等于死路。`ResultListener` 还是静态单 listener（后注册覆盖先注册），并发下会串。`code` 只在弃用方法里赋值，所以 Activity 里那段 `switch (getCode())` 的 6 个 case（100/150/200/500/600/700/750）**在现行路径下永不生效**。

建议：新代码一律走口 1，口 3 只作兼容保留。

## 四、结果格式

### Intent 契约

| 项 | 值 |
|---|---|
| 请求 extra 键 | `"config"`（`FileBrowser`，`Serializable`） |
| 结果 extra 键 | `SELECTED_FILES` = `"SELECTED_FILES"` |
| 结果类型 | `ArrayList<Uri>` |
| 结果码 | 确认 `RESULT_OK`；返回/关闭 `RESULT_CANCELED` |

读取：`FileBrowser.getSelectedFiles(intent)`，返回 `List<SelectedFile>`。

| 情形 | 返回 |
|---|---|
| `data == null` | `null` |
| extra 缺失或为空 | 空列表（`Collections.emptyList()`） |
| 正常 | 元素个数与选中一致 |



<!-- ✓ -->

### Uri 的两种形态

| 来源 | Uri 形态 | `uri.toString()` |
|---|---|---|
| 内置浏览器选中 | 无 scheme，仅路径 | `/storage/emulated/0/...` |
| 系统选择器（`selectExternal`） | `content://` | `content://...` |

内置路径那一种是先存绝对路径字符串、再用 `Uri.parse()` 转出来的，`getPath()` 与 `toString()` 都等于原绝对路径。

<!-- ✓ -->

### `SelectedFile` 字段

| 成员 | 说明 |
|---|---|
| `isContent` | `uri.scheme == "content"` |
| `file` | 本地返回 `File`；content 返回 `null` |
| `path` | `uri.toString()` |
| `fileName(context)` | content 走 `OpenableColumns.DISPLAY_NAME`，失败回退 `lastPathSegment`，再失败返回 `"unknown"`（已对 `SecurityException` 兜底） |
| `openInputStream(context)` | content 走 `ContentResolver`，本地走 `File.inputStream()` |
| `toFile(context, cacheDir)` | 本地直接返回；content **拷贝到 cacheDir 后返回副本** |
| `copyTo(context, dest)` | 拷贝到指定文件；**异常被静默吞掉** |

⚠ `copyTo` 失败不抛也不返回布尔值 —— 调用方拿不到失败。需要知道成败的地方要自己判文件是否存在。

## 六、底层操作 `FileOperator`

| 方法 | 行为 |
|---|---|
| `getFileList(path, config, sortMode)` | 列目录，目录优先；`FOLDER_CHOOSER` 只留目录 |
| `isValidFileName(name)` | 非空、非纯空格、不含 `/` 与 `File.separator` |
| `resolveConflict(dir, name)` | 重名追加 ` (1)`、` (2)`…，保留扩展名 |
| `createDirectory` / `createFile` | 已存在则抛 |
| `rename` | 用 `Files.move`；目标已存在则抛 |
| `delete` | `FileUtils.forceDelete`（目录递归删） |
| `copyTo` / `moveTo` | 逐个处理，单个失败只记日志，**返回成功数量** |

命名冲突规则要点：`resolveConflict` 只在 `dot > 0` 时拆扩展名，所以 `.gitignore` 这类点开头文件不会被拆。

<!-- ✓ -->

### 会话剪贴板 `FileClipboard`

进程级单例，只存当前勾选的 `List<File>` 与 `isCut`。**进程退出即清空，不跨会话。** 剪切粘贴成功后调用 `clear()`；复制粘贴后不清空（可重复粘贴）。

## 七、游戏内目录浏览（`OpenFolderDialog`）

触发点：`KCUBridge` 处理游戏内链接时，若链接解码后是目录，就弹这个对话框。

- 内嵌 `FileBrowserAdapter`，强制 `FILE_BROWSER` + `SortMode.NAME`
- 起始目录由调用方给，返回上级限制在起始目录之内（不允许跳出）
- 「导入」按钮走 `launchMultiSelection(targetDir, null)`（不限后缀），把选中文件拷进当前目录
- 导入在 `Dispatchers.IO` 协程里逐个拷，可取消；单个失败弹对话框显示文件名与堆栈
- 绕过：直接用 `FileBrowserAdapter` 而不启动 `FileBrowserActivity`

## 八、对外暴露（`FolderProvider`）

`scoped/FolderProvider` 是 `DocumentsProvider`，让 MT 管理器等第三方通过 SAF 访问本应用目录。

| 项 | 值 |
|---|---|
| manifest authority | `${applicationId}.document.provider` |
| 导出 | `exported="true"` |
| 权限 | `android.permission.MANAGE_DOCUMENTS` |
| intent-filter | `android.content.action.DOCUMENTS_PROVIDER` |

文档 id 结构：`<packageName>/data/<子路径>` 或 `<packageName>/android_data/<子路径>`。

| 段 | 对应目录 |
|---|---|
| `data` | `getFilesDir().getParentFile()`（即 `/data/data/<pkg>`） |
| `android_data` | `getExternalFilesDir(null).getParentFile()` |

实现的 `DocumentsProvider` 方法：`queryRoots`、`queryDocument`、`queryChildDocuments`、`openDocument`、`createDocument`、`deleteDocument`、`removeDocument`、`renameDocument`、`moveDocument`、`getDocumentType`、`isChildDocument`、`call`。

额外非标准方法与列：`mt:setLastModified`、`mt:setPermissions`、`mt:createSymlink`、`mt_extras`、`mt_path`。

⚠ 这等于把私有目录开放给第三方读写。**开源或分发前若不想暴露，需去掉 manifest 里这段 provider 声明。**

<!-- ✓ -->

### 分享与外开（`FileProvider`）

| 项 | 值 |
|---|---|
| manifest authority | `${applicationId}.provider` |
| 路径配置 | `res/xml/provider_paths.xml`（external / cache / files 三种，path 均为 `.`） |

两处调用**写法不一致**（这是个真实隐患）：

| 位置 | 用的 authority |
|---|---|
| `openExternal` | `getApplication().getPackageName() + ".provider"`（随变体变化，正确） |
| `shareFile` | `getString(R.string.file_browser_provider)` = 写死的 `com.kcu.launcher.provider` |

`applicationId` 为 `com.kcu.launcher`，debug 变体带后缀 `.debug`。**因此 debug 构建下"分享"会因 authority 不匹配抛异常**，release 正常。改成与 `openExternal` 同一写法即可。

## 十二、改这个文件管理时的检查项

1. 新增入口 → 用 `FileBrowserLauncher`，不要用 `browse()`。
2. 新格式 → 后缀列表只影响文件，目录永远可见。
3. 只要目录 → 用 `isDirectory = true`，别指望后缀过滤。
4. 结果可能 `null`，也可能空列表 —— 两种都要处理。
5. 结果是 content uri 时，临时授权随时失效 → 要落盘就用 `toFile(context, cacheDir)`。
6. `FileOperator` 的批处理返回成功数量，不是布尔值；失败不抛。
7. 动 manifest 组件名 → 先确认源码 `package` 行，别照抄旧副本。
8. 分享/外开统一用 `getPackageName() + ".provider"`。
