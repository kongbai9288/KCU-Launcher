## 1. 事故：编译失败被报成成功

### 1.1 起因

本轮按要求对既有代码做严格审核。读到 `KcuDevMode.java:195` 时发现：

```java
OutputStream out = null;          // 裸用
```

而 import 区只有 13 行，**不含 `java.io.OutputStream`**。按 Java 规则这必然编译失败。但此前连续多轮报告"Build release 均 success"。两者矛盾。

### 1.2 实验

注入一行明确的语法错误：

```java
public static void __syntax_canary() { THIS_IS_A_SYNTAX_ERROR_CANARY; }
```

触发编译，观察结果。

| 观察项 | 结果 |
|---|---|
| job conclusion | **success** |
| 该 run 的 artifacts | **0 个** |
| 创建的告警 issue | **5 条**（#290–294，五个架构各一条"build 失败"） |

**编译确实失败，告警确实发出，但 job 显示 success。**

### 1.3 根因

`build.yml` 第 88–91 行：

```bash
./gradlew assembleRelease ... 2>&1 | tee /tmp/build.log
GE=${PIPESTATUS[0]}
if [ "$GE" -eq 0 ]; then
  echo "GRADLE_OK=true"  >> "$GITHUB_ENV"
else
  echo "GRADLE_OK=false" >> "$GITHUB_ENV"
fi
```

`GE` 拿到了真实退出码，但**没有任何一步因此以非零状态退出**。step 的最后一条命令是 `echo`，永远成功 → step 成功 → job 成功。

`GRADLE_OK=false` 只喂给 issue 上报步骤，**与 job 结论完全脱钩**。

### 1.4 影响

**v0.17.0 起，编译实际一直失败，APK 从未产出**，而每轮都报告 success。

真实错误（从告警 issue 正文的编译日志尾部取出）：

```
KcuNativeSync.java:153: error: incompatible types: Set<String> cannot be converted to List<String>
        writeLines(record, kept);
1 error
> Task :FCL:compileReleaseJavaWithJavac FAILED
```

这是 v0.17.0 加入 `KcuNativeSync` 时写下的类型错误。`prune(File, Set<String>)` 直接把 `Set` 传给了需要 `List<String>` 的 `writeLines`。

---

## 2. 修复

### 2.1 workflow（三处）

| 改动 | 目的 |
|---|---|
| Build release / debug 末尾加 `if [ "$GE" -ne 0 ]; then echo "::error::..."; exit 1; fi` | gradle 失败时 step 真的失败 |
| 列出产物 / 验证签名 / Upload APK 加 `env.GRADLE_OK == 'true'` | 不让旧产物或空目录伪装成功 |
| 补 `set -o pipefail` | 管道退出码语义明确 |

**修改中自查抓到的新 bug**：批量替换 `if: steps.guard.outputs.has_source == 'true'` 时，把 `Grant execute permission` 也加上了 `GRADLE_OK == 'true'`。该步骤在 `GRADLE_OK` 被赋值之前执行，条件恒为 false → `chmod +x gradlew` 不执行 → 编译必然 `Permission denied`。**已恢复原条件。**

### 2.2 源码

- 删除 `KcuDevMode.create()`：无调用点（死代码），且写入的内容 SHA3 永远不等于期望值（是个会让人误以为"调用它就能开启"的陷阱）。连带解决 `OutputStream` 缺 import。
- `KcuNativeSync.prune`：`Set` 排序后转 `List` 再写入，避免遍历顺序导致记录文件内容抖动。

## 5. 审核中查出但本轮未修的缺陷

按严重度排序，待编译验证稳定后逐项修。

| # | 文件 | 缺陷 | 后果 |
|---|---|---|---|
| 1 | `KcuDevMode` | `isEnabled()` 结果永久缓存，无失效机制 | 玩家放好开关文件后，不重启且不点"重新检测"就不生效，**静默** |
| 2 | `KcuAccountFlow.resolve` | 未找到同名账号时返回**任意第一个非离线账号** | 玩家输入 "Steve" 却用 "Alex" 的账号进游戏，与"按名称进入"的设计直接矛盾 |
| 3 | `KcuUi` | `setCornerRadius(RADIUS_DP * 3)` 传的是**像素不是 dp** | 高密屏上圆角约 4dp，与设计稿 10dp 不符；违反自身规则 |
| 4 | `KcuUi` | 颜色全部硬编码，未用已新增的 `kcu_*` 亮暗资源 | 深色模式下 `INK_2`(55534C) 压在深底上几乎不可读 |
| 5 | `KcuDevMode.clearMarks` | `KcuAgeGate.reset()` 无条件 `cleared++` | 计数虚报，页面显示"已清除 3 项"可能只删了 1 个文件 |
| 6 | `KcuDevMode.verifyOwner` | 用全文 `contains("kongbai9288")` 判定 | 他人 token 的 bio/name 等字段含该字样即误判通过；应解析 login 字段精确比对 |
| 7 | `KcuAccountFlow.isValidName` | 只允许字母数字下划线 | 中文名被拒，**且无提示** |
| 8 | `FCLPath` | `KCU_SHARED_ROOT` 为 public 非 final，各派生字段求值时机不一（部分声明时、部分 `loadPaths` 时） | 脆弱；一旦被改，目录不一致 |
