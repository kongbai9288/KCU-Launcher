# 文档维护规程（每轮必更新清单）

执行者：yuanbao，2026-10-22 建立

---

## 1. 为什么有这份文档

此前每轮只更新了**新增专题文档 + 改动台账 + version_map + CHANGELOG** 四份，其余文档长期不更新，导致：

- `docs/00-总览/README.md` 的"项目状态"长期停留在"阶段 0 进行中、未编译过任何 APK"，而实际已编译 30 轮、产出 5 架构产物
- `README.md` 功能第 2 条仍写"主题可自定义"，而 v0.26.0 已把主题自定义整体移除 —— **文档与产品矛盾**
- `docs/03-防错/README.md` 未随轮次追加规则
- `docs/01-架构/README.md` 未反映主题引擎拆解、公告/更新源/推广停用

文档不是附属品，是这个项目对抗上下文丢失的唯一手段。文档与实现脱节，等于没有文档。

---

## 2. 每轮必更新清单

按顺序执行，缺一不可。

| # | 文件 | 更新内容 | 判据 |
|---|---|---|---|
| 1 | `docs/00-总览/改动台账.md` | 按文件记录本轮改了什么、为什么、有什么坑 | 每个被改文件都有条目 |
| 2 | `docs/00-总览/README.md` | **项目状态**（已/未验证清单）+ **决策记录**（本轮新增决策） | 状态与实际一致 |
| 3 | `docs/03-防错/README.md` | 本轮踩到的坑、新增硬规则 | 有新坑就有新规则 |
| 4 | `CHANGELOG.md` | 版本号 + 日期 + 变更 + 执行者 **yuanbao** + 审核哈希 | 有版本就有条目 |
| 5 | `version_map.json` | 新增版本条目，含 `author: yuanbao` | 与 CHANGELOG 同步 |
| 6 | `build.gradle.kts` | `versionName` / `versionCode`（**唯一真源**） | 与 version_map 一致 |
| 7 | **本轮新增专题文档** | 放对应分类目录 | 有实质改动就有文档 |
| 8 | `docs/01-架构/README.md` | 架构分层/目录策略若发生变化 | 结构变了就改 |
| 9 | `README.md`（根） | 功能、用法、目录布局若发生变化 | **尤其检查是否被本轮改动推翻** |

---

## 3. 第 9 条最关键：检查根 README 是否被推翻

根 README 是对用户的承诺面。代码改了而 README 没改，就是**对用户的虚假陈述**。

本轮实例（v0.26.0 引入、v0.31.0 才发现）：

| README 写的 | 实际 |
|---|---|
| 「几乎一切可自定义：…、主题」 | v0.26.0 起主题配色不可自定义，四个配色项、alpha、亮暗背景图设置项已删除 |

**修正**：把"主题"从可自定义清单中移除。

**规则**：每轮结束前，逐条比对根 README 的功能列表与本轮改动，凡被推翻的立即改。

---

## 4. 项目状态的写法（禁止自我欺骗）

`docs/00-总览/README.md` 的"项目状态"必须区分三类：

| 类别 | 含义 | 写法 |
|---|---|---|
| **PROVEN** | 有产物/命令输出为证 | 写明证据（run id、字节数） |
| **NOT PROVEN** | 未验证 | 明确写"未验证" |
| **BLOCKED** | 可命名但无法执行 | 写明缺什么 |

禁止把 NOT PROVEN 写成 PROVEN，禁止用"应该可以""理论上"糊过去。
