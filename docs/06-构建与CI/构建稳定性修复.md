# 构建稳定性修复（v0.42.0）

执行者：yuanbao，2026-10-24

---

## 1. 起因：一次 arm 构建失败，暴露两个基础设施缺陷

v0.41.0 上传三个文件（间隔 2 秒），触发 **3 个并发构建**：

| run | 时间(UTC) | 结论 | 产物 |
|---|---|---|---|
| 39981919934 | 15:51:56 | success | 5 |
| 39981924375 | 15:51:58 | success | 5 |
| 39981928323 | 15:52:00 | **failure** | 4（arm 缺） |

失败日志尾部：

```
Caused by: java.util.zip.ZipException: Archiv...
```

**不是代码错误** —— 同样的代码在 39981924375 里 5 个架构全过。

---

## 2. 两个缺陷

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | 无并发控制 | 一次提交触发 3 个构建，浪费 CI 时间，且并发下载依赖易损坏归档 |
| 2 | gradle 失败即终止 | 瞬时故障（下载损坏）直接判失败，无法自愈 |

---

## 3. 修复

### 3.1 并发控制

```yaml
concurrency:
  group: build-${{ github.ref }}
  cancel-in-progress: true
```

同一 ref 只保留最新一次构建。

### 3.2 gradle 首次失败重试一次

```bash
run_once() { ./gradlew assembleRelease ... ; return ${PIPESTATUS[0]}; }
run_once; GE=$?
if [ "$GE" -ne 0 ]; then
  echo "::warning::首次构建失败（退出码 $GE），重试一次"
  run_once; GE=$?
fi
```

**真实编译错误重试仍会失败**，最终结果不被掩盖，只是多花一次构建时间。

## 7. 严格审核

### 7.1 会导致什么错误

| # | 错误 | 处置 |
|---|---|---|
| 1 | `cancel-in-progress` 取消掉正在跑的、其实需要的构建 | 只在**同一 ref** 内取消；不同分支互不干扰 ✅ |
| 2 | 重试掩盖真实编译错误 | 重试后仍失败即失败，最终结果不变 ✅ |
| 3 | 重试把日志覆盖掉 | `tee` 不带 `-a`，第二次完整重写 `/tmp/build.log` ✅ |
| 4 | 并发组名用 `github.ref` 导致 tag 与分支冲突 | 组名含完整 ref，不冲突 ✅ |
| 5 | YAML 语法错误导致 workflow 失效 | 本地 `yaml.safe_load` 校验通过 + 实跑验证 ✅ |

### 7.2 对用户使用逻辑的影响

无直接影响（CI 内部行为）。

### 7.3 对未来的影响

| # | 影响 | 评估 |
|---|---|---|
| 1 | 连续 push 不再产生重复构建 | 节省 CI 时间 |
| 2 | 瞬时故障自动恢复 | 减少假失败 |
| 3 | 需 dispatch 多次验证多架构时会互相取消 | ⚠ 已知限制：并发组会取消前一次 |

### 7.4 对代码逻辑的影响

无 —— 只改 workflow 文件。
