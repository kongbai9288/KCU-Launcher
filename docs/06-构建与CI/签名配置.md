## 2. 踩到的关键坑：扩展名骗人

签名文件名为 `*.jks`，但实测：

| 检查项 | 结果 |
|---|---|
| 文件头 16 字节 | `30820a7e02010330820a2806092a8648` |
| JKS magic | ❌ 不是 `0xFEEDFEED` |
| `keytool -list -storetype pkcs12` | ✅ 成功 |
| `Keystore type` | **PKCS12** |

`0x30 82` 是 ASN.1 DER SEQUENCE 头 —— **这是一个 PKCS12 库，只是沿用了 .jks 扩展名**。

不显式声明 `storeType` 时 AGP 按 JKS 解析会失败。已修：

```kotlin
storeType = System.getenv("KCU_STORE_TYPE") ?: "pkcs12"
```

留了环境变量覆盖位，将来换真 JKS 不用改代码。

**教训：不要相信扩展名，看文件头。**

## 3. 另一个坑：密码文件解析

`pass.txt` 形如：

```
签名信息：

- Keystore 密码：xxxx
- Key 别名：kbs
- Key 密码：xxxx
```

第一版解析按空格 split，把 `- Keystore 密码：Wl...` 拆成 `["-", "Keystore", "密码：Wl..."]`，结果取出的值带中文前缀，**4 个候选密码全部解锁失败**。

改成按全角冒号 `：` 取最后一段才对。

## 4. 配置清单

### 4.1 Secrets（已用 libsodium sealed box 加密写入）

| Secret | 内容 |
|---|---|
| `KCU_KEYSTORE_BASE64` | keystore 的 base64（3588 字符） |
| `KCU_KEYSTORE_PASSWORD` | store 密码 |
| `KCU_KEY_ALIAS` | `kbs` |
| `KCU_KEY_PASSWORD` | key 密码 |

密码**从未写入任何仓库文件**，也不在本仓库的任何提交里。

### 4.2 构建链路

```
secrets → base64 -d → ./key-store.jks（仓库根，构建期临时）
        → AGP signingConfigs.FCLKey
        → storeType=pkcs12
        → v2 + v3 签名（v1 关闭，minSdk 26 无需）
```

`key-store.jks` 在 CI 工作区生成，**不提交**（`.gitignore` 已含）。

### 4.3 兜底

`useReleaseSign = file("key-store.jks").exists() && !pwd.isNullOrEmpty()`

签名库缺失或密码为空时**回退 AGP 默认 debug 签名，构建不失败**。
