# 输入方案修正：为什么不该改 Java 触摸层

> **本文档撤销 `输入问题诊断.md` 中的「路径 B：最小补丁」。**
> 用户的判断成立，且有官方证据支撑。执行者：yuanbao，2026-10-19。

## 1. 撤回路径 B

上一轮我建议：在 `TouchPad.java` / `ControlButton.java` 补 `getHistorySize()` 遍历，放宽点击阈值。

**这个建议撤回。理由如下。**

### 1.1 官方明确警告：启动器手势与游戏内输入会打架

TouchController 在 CurseForge 页面的原文：

> 注意：请禁用手机上启动器（例如 PojavLauncher 和 FoldCraftLauncher）自带的触摸手势，否则会出现**预料之外的鼠标输入**，尤其是你按下屏幕上的按钮的时候。

官方 wiki 更进一步，直接教用户删除启动器控件：

> 隐藏启动器的控件 —— 大部分启动器都有控件编辑功能，您可以删除启动器自带的控件。**以 FCL 为例，您只需要新建一个空布局，删除原布局后进入游戏**，便可以看到启动器自带的控件已被删除。

这不是个别现象，是**结构性冲突**：启动器层的手势翻译成鼠标事件，与游戏内 mod 自己接管的触摸输入，两套语义叠在同一条链路上。

### 1.2 MC 侧的固有毛病（用户指出的两个点，都成立）

**① 灵敏度是立方非线性**

```
f = mouseSensitivity * 0.6 + 0.2
g = f * f * f * 8.0
Δ = g * dx * 0.15
```

即 `(0.6s + 0.2)³ × 1.2`。后果：sens 0.2 不是 0.1 的两倍快；换 DPI 后手感完全对不上。社区专门做了 mod 来修（`Linear Sensitivity`，Modrinth，3.3K 下载，用单个 mixin 改 `updateMouse()`）。

**② `touchscreen` 是 MC 内置选项**

`options.txt` 里有 `touchscreen`（布尔，默认 false）。开启后 MC 的物品栏交互行为改变，走基岩版式的两段式点击。启动器若不同步处理这个开关，GUI 交互就会"检测不到"。

### 1.3 结论

在启动器 Java 层加历史点遍历，等于**在错误的层级做修正**：

- 它无法感知 MC 的 `touchscreen` 开关
- 它经过 `pushEventLookDelta` 到 native 侧，语义已在游戏外
- 它与游戏内 mod 的触摸接管直接冲突
- 而 MC 视角本身的病（立方灵敏度、符号、帧同步）它一个都治不了

**用户"这两行代码会跟原本正常的转动起冲突"的判断，正确。**

## 2. 更好的项目：TouchController

| 项 | 值 |

| Stars | 212 |
| 最近更新 | 2026-10-14（活跃） |
| 定位 | 「一款 Minecraft：Java 版的模组，添加了类基岩版的触摸控制系统」 |

### 2.1 为什么它是对的解法

**它在游戏内，不在启动器。**

架构原文：

> TouchController 的**平台输入代码和实际的输入处理代码部分是相互隔离开的**

即：触摸事件在游戏进程内被 MC 自己接收和处理，不需要经过启动器的"手势 → 鼠标事件"翻译。这直接绕开了 §1.1 的冲突。

**通信方式**：启动器侧集成 `proxy-client` 库，选定 UDP 端口，启动时通过 `TOUCH_CONTROLLER_PROXY` 环境变量传给游戏，用 `localhostLauncherSocketProxyClient` 发送触控消息。

对 KCU Launcher 来说这是好消息：启动器侧只需要**转发**，不需要实现任何手势逻辑。

## 3. 修正后的方案

### 3.1 输入层：不修启动器，交给 TouchController

| 层 | 谁负责 | KCU 做什么 |
|---|---|---|
| 触摸手势、视角、GUI 交互 | **TouchController（游戏内 mod）** | 集成 `proxy-client`，传 `TOUCH_CONTROLLER_PROXY` |
| 启动器自带控件 | 用户按需保留 | **提供一键「空布局」**，让用户能彻底关掉 |
| 视角灵敏度病 | `Linear Sensitivity` mod（可选） | 在模组推荐列表里列出 |

### 3.2 上一轮三个问题的重新归因

| 问题 | 上一轮归因 | 修正后 |
|---|---|---|
| 滑动过程检测不到 | 未遍历历史点 | 层级错误，应在游戏内由 TouchController 处理 |
| 点击难受 | 100ms/10px 过严 | 同上；且 `touchscreen` 开关未同步会放大此问题 |
| 点不到位置 | `SLIDE` 模式 | **仍成立**，切 `CLICK` 是零改码解法，保留 |

只有第三条的原判保留，前两条撤回。

### 3.3 保留的零改码建议

- 切 `MouseMoveMode.CLICK`
- 提供空布局入口，配合 TouchController 使用

## 5. 一句话

**不要在启动器层跟 MC 的输入病较劲。把手势处理下移到游戏内，启动器只做转发和让路。**
