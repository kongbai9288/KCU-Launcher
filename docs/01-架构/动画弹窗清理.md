## 2. 关键判断

### 2.1 `AnimationDialog` 的两处命中是假阳性

`DialogCard.kt:24`：

```kotlin
/** 对话框内选中条目背景：主题色半透明圆角底（与 AnimationDialog 选中行一致） */
```

`RightMenuAdapter.kt:579`：

```kotlin
// 条目卡片背景：以对话框背景为基准微亮，暗色下仅微亮避免刺眼（与 AnimationDialog 行样式一致）
```

**两处都在注释里」，不是 import 也不是调用。** 这是规则 196 的典型场景：code search 命中不等于引用，必须逐条看上下文。

结论：`AnimationDialog` 是**真正的死代码**。

### 2.2 `SkinAnimations.kt` 不能删

它提供 `restoreSkinSwitches()`，注释明写"供主界面之外其他使用皮肤模型的地方保持一致的显示效果"。全仓确认 **两个账号皮肤 Dialog 在调它**。删了会直接编译失败。

这正好印证上轮事故教训：删文件前必须沿调用链向上追。

### 2.3 布局可以删

`dialog_animation_switch.xml` 与 `item_animation.xml` 用 `filename:` 限定符检索，各只有文件自身 1 处命中，**无 `include`、无其他布局引用**。`AnimationDialog.kt` 删除后这两个布局失去唯一消费者，一并删除。
