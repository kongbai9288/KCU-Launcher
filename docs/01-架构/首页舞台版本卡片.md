## 3. 严格审核

### 3.1 会导致什么错误

| # | 错误 | 处置 |
|---|---|---|
| 1 | **我第一版加了 `@Override public void onStart()`，会编译失败** | 源码注释明示「皮肤渲染随页面挂载/回收恢复与暂停（**替代原 onStart/onStop 生命周期**）」——`FCLCommonUI` 没有 onStart/onStop。已改为挂在已有的 `OnAttachStateChangeListener.onViewAttachedToWindow` 里 |
| 2 | **ElementTree 写回后 SkinViewer 同时存在 `Top_toTopOf` 与 `Top_toBottomOf`** | ET 是在原属性上追加，没删旧的。已**手工重写**整个 XML，校验 top 约束数 = 1 |
| 3 | ET 写回把格式压成单行 | 同上，手工重写恢复缩进与 `android:`/`app:` 前缀 |
| 4 | `Profiles.getSelectedVersion()` 返回 null 或空 | 判空后显示 `kcu_stage_version_none`，不 NPE |
| 5 | 新增 id 与已有 id 冲突 | `stage_card` / `stage_version` 全局检索无同名（v0.28.0 已把 `title`/`date`/`hide` 等删干净） |
| 6 | 新增视图数 | 3 个（容器 + 2 个 TextView），低于「单次搬入 ≤ 4 个」的硬规则 |

### 3.2 对用户使用逻辑的影响

| 路径 | 结果 |
|---|---|
| 打开首页 | 顶部卡片显示「当前版本 / <版本 id>」；未选版本时显示「未选择」 |
| 在版本页切换版本后回首页 | attach 回调重画，显示新版本 ✅ |
| 首页 → 版本页 → 返回首页（未重建视图） | 不经过 attach，**不会刷新** ⚠️ 见下 |
| 旋屏、切后台再回来 | 视图重建 → attach → 刷新 ✅ |
| 皮肤预览 | 高度从 80% 降到 70%，顶部让位给卡片，不重叠 ✅ |

**已知局限**：`onViewAttachedToWindow` 只在视图挂载时触发。若首页与版本页是两个 UI 且切换时不重建首页视图（FCL 的 UI 管理器多为 `switchUI` 重建），则版本变化不会实时反映。是否成立需实机确认。

### 3.3 对未来的影响

| # | 影响 | 评估 |
|---|---|---|
| 1 | 首页有了信息承载点，后续加实例名、加载器图标有了落位 | 正向 |
| 2 | `refreshSelectedVersion()` 是 public，可被 `MainActivity` 主动调用 | 预留了实时刷新入口 |
| 3 | SkinViewer 高度降到 70% | 若用户觉得模型变小，可调回 |

### 3.4 对代码逻辑的影响

| # | 影响 | 评估 |
|---|---|---|
| 1 | `MainUI` 多一个 public 方法与一次 findViewById | 开销可忽略 |
| 2 | 首页 inflate 视图数 2 → 5 | 可接受 |
| 3 | 未改动任何上游启动/渲染逻辑 | ✅ |
