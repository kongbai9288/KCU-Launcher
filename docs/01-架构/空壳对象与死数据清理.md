## 3. 严格审核

### 3.1 会导致什么错误

| # | 错误 | 处置 |
|---|---|---|
| 1 | **删 `LEGACY_FILE_NAMES` 里的文件名会导致旧文件永远不被清理** | **保留文件名**。原因见下 |
| 2 | 只删 `QuarkPromo.kt` 不改 MainActivity → 编译失败（unresolved reference） | **先改调用方再删文件** |
| 3 | 平铺 lambda 时括号不配对 → 编译失败 | 校验 `{`=219 `}`=219、`(`=623 `)`=623 |
| 4 | 删 `LaunchCountSetting` 类但保留字段 → 编译失败 | **三处一起删**（类、字段、迁移行） |
| 5 | 旧 `app_settings.json` 含未知字段 `launchCount` | kotlinx.serialization **默认忽略未知字段**，走默认值 |

### 3.2 为什么必须保留 legacy 文件名

这是本轮唯一有实质风险的判断点：

```kotlin
private fun legacyFiles(): List<File> =
    dir.listFiles { file -> file.isFile && file.name in LEGACY_FILE_NAMES }?.toList().orEmpty()

override suspend fun shouldMigrate(currentData: AppSettingsPreference): Boolean =
    legacyFiles().isNotEmpty()
```

`LEGACY_FILE_NAMES` 有**两个**作用：
1. 供 `readLegacy<T>()` 读取（本轮已删该读取）
2. **供 `legacyFiles()` 判断"旧文件是否全部消失"→ 决定 shouldMigrate 与 cleanUp**

如果跟着把文件名也删了，那么设备上残留的 `launch_count_settings.json` 就**不再被识别为 legacy 文件**：
- `shouldMigrate` 对它视而不见
- `cleanUp()` 不会删除它
- 该文件永久残留在 `datastore/` 目录

**所以：删读取，保留文件名。** 这样旧文件仍会被识别、被清理，只是不再解析到已删的数据类。
