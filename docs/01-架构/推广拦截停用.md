# 上游网盘推广拦截停用（v0.30.0）

执行者：yuanbao，2026-10-22

---

## 1. 追溯到底

```
QuarkPromo (object)
  ├─ PREF_KEY_NETDISK_URL = "quark_netdisk_url"（SharedPreferences "launcher"）
  ├─ updateNetdiskUrl(context, url)      ← 原由 UpdateChecker.check() 调用
  ├─ interceptLaunch(activity, onProceed) ← MainActivity 启动游戏前调用
  │    ├─ 非中文/非大陆 → 直接放行
  │    ├─ 读缓存链接
  │    ├─ pendingPopup && 有链接 → 直接弹窗
  │    ├─ 掷骰子 Random.nextDouble() < popupProbability(pity)
  │    └─ 中签 → showDialog：点「打开网盘」跳浏览器并取消启动；点「开始游戏」才继续
  └─ popupProbability(count)：基础 0.6%，第 80 次起 +10%/次，第 90 次必弹

MainActivity 调用点确认：搜索 QuarkPromo 命中 5 处，源码仅 QuarkPromo.kt 自身 + MainActivity.kt。
```

**这是上游内置的推广机制**：按启动次数累积保底概率，中签后弹窗引导跳转外部网盘链接，且**点「打开网盘」会取消本次游戏启动**。

---

## 2. 现状分析：功能上已半死，但风险仍在

v0.29.0 停用 `UpdateChecker` 后，`updateNetdiskUrl` 不再被调用 → 缓存链接恒为 null。

按现有逻辑推演：

| 条件 | 行为 |
|---|---|
| `shown=true` 但 `netdiskUrl==null` | `pendingPopup=true`，走 else 分支 `onProceed()` → **不弹窗** |
| 下次启动 `pendingPopup=true` 且仍无链接 | 仍走 else，永远不弹窗 |

**所以当前实际上不会弹窗。** 但保留它有三个问题：

1. 每次启动仍在掷骰子、仍在写 `appSettingsDataStore`（累计 `pityCounter` / `totalLaunchCount`）
2. `pendingPopup` 一旦置 true 就永远 true，是个脏状态
3. **只要有任何路径写入 `quark_netdisk_url`，第 90 次必弹的机制立刻复活**

---

## 3. 改动

| 文件 | 改动 |
|---|---|
| `QuarkPromo.kt` | `updateNetdiskUrl` → no-op；`interceptLaunch` → 直接 `onProceed()`；删 `showDialog`、`popupProbability`、`PREF_KEY`；清 11 个失效 import。**92 → 22 行** |
| `values/strings.xml`、`values-zh/strings.xml` | 删 4 个 `quark_promo_*` 字符串 |

**保留**：`QuarkPromo` 对象与两个方法签名 —— `MainActivity` 调用点零改动。

其余 11 个语言目录没有 `quark_promo_*` 键（脚本按"有则删"处理，实际只有 2 个文件命中）。

## 4. 严格审核

### 4.1 会导致什么错误

| # | 错误 | 处置 |
|---|---|---|
| 1 | 只删方法体不删 `showDialog` → 死方法残留 | **已删**（确认无别处引用） |
| 2 | 删 `popupProbability` 前未确认引用 | 搜索 **total=1**，仅自身；已删 |
| 3 | `@JvmStatic` 在 Kotlin 无需显式 import（默认导入含 `kotlin.jvm.*`） | 原文件本就没有该 import，保持原样 ✅ |
| 4 | 删 import 时误删仍在用的 | 脚本按"body 出现次数为 0"才删，逐个校验 |
| 5 | 删 `quark_promo_*` 字符串但别处仍引用 | 已在删 `showDialog` 后无引用；且未引用资源不报错，最坏也只是残留 |
| 6 | `interceptLaunch` 参数 `activity` 未使用 | Kotlin 允许未使用参数，不报错 ✅ |

### 4.2 对用户使用逻辑的影响

| 路径 | 结果 |
|---|---|
| 点「启动游戏」 | **不再有任何拦截弹窗，直接进入** ✅ |
| 启动计数 | 不再累积 `totalLaunchCount` / `pityCounter` |
| 中文大陆用户 | 与非大陆用户行为一致（原本就放行） ✅ |
| 残留 `pendingPopup=true` 的老用户 | 该字段不再被读取，无影响 ✅ |

### 4.3 对未来的影响

| # | 影响 | 评估 |
|---|---|---|
| 1 | 启动路径少一次协程 + DataStore 读写 | 启动略快 |
| 2 | 若将来要做自有推广/公告 | 需新建机制，不复用此类 |
| 3 | `appSettingsDataStore.launchCount` 字段不再被写 | 该字段是否还有别处使用未确认，记入待办 |
| 4 | `QuarkPromo` 成为空壳对象 | 下轮可整体删除（连同 MainActivity 调用点） |

### 4.4 对代码逻辑的影响

| # | 影响 | 评估 |
|---|---|---|
| 1 | `QuarkPromo.kt` 92 → 22 行 | 只剩两个 no-op 签名 |
| 2 | `MainActivity` 启动回调链缩短一层 | 少一个异步分支，时序更简单 |
| 3 | 随机数与概率逻辑移除 | 启动行为**确定化**（原本带随机性） |

**启动行为确定化**是这一项最实质的收益：原来"这次启动会不会被弹窗打断"是随机的，现在必然不会。
