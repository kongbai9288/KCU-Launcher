## 1. 开关改为 SHA3-256 校验

位置：`/sdcard/KCU/dev_mode`

**存在性不再生效**，必须内容哈希一致：

```
4c238702173b7a01d082f2c6f840d8f149e28e6b081a60e54b452d7c9c5453e0
```

文件不存在 / 为空 / 超过 64MB / 哈希不符 → 一律关闭。结果缓存，`clearMarks()` 后刷新。

### 自行实现 SHA3-256 的原因

`MessageDigest.getInstance("SHA3-256")` 由 Java 9 的 SUN provider 引入，Android 各版本支持不一致，部分设备会抛 `NoSuchAlgorithmException`。

### 算法验证

复刻同一套 Keccak 逻辑与标准库比对，四个向量全过：

|---|---|
| 空串 | PASS |
| `abc` | PASS |
| 10000 字节（跨块） | PASS |
| 目标文件 23652 字节 | PASS |

## 3. 模拟使用逻辑审查出的真 bug

### 3.1 年龄声明永远存不下

**推演路径**：冷启动 → `SplashActivity.onCreate` → `KcuAgeGate.isDeclared()`

实际时序：

```
onCreate → 检查协议 → checkPermission → init() → enterLauncher() → ConfigHolder.init()
```

`ConfigHolder.init()` 在 `enterLauncher()` 里才执行，而拦截在 `onCreate` 最前。

`ConfigHolder.config()` 源码：

```java
public static Config config() {
    if (configInstance == null) {
        throw new IllegalStateException("Configuration hasn't been loaded");
    }
    return configInstance;
}
```

**未初始化直接抛异常。** 我的 try-catch 吞掉后返回 false：

- `isDeclared()` 恒 false → **每次冷启动都弹年龄页**
- `declare()` 同样抛异常 → **点了确认也不保存**

用户表现：选完年龄进主界面，下次打开又让选，反复循环。

**修法**：改存独立 SharedPreferences，不依赖 `ConfigHolder`。`clearMarks()` 同步改为调 `KcuAgeGate.reset()`。
