## 1. 上轮遗留的严重回归（本轮修复）

v0.21.0 把底色换成浅纸后，未同步检查依赖它的取色链路：

```
KCUTextView  app:auto_text_tint="true"
  → refreshTheme() → setTextColor(ThemeData.autoTint)
      → 原实现：luminance(getColor()) >= 0.5 ? BLACK : WHITE

KCUMenuView  refreshTheme()
  → setImageTintList(ThemeData.autoTint)
```

主色 `#3D6B66` 亮度约 0.13 < 0.5 → **autoTint 恒为白色**。

| | 上轮前 | 上轮后 |
|---|---|---|
| 左栏底 | 主色实心块（白图标可见） | 透明 → 白图标落在浅纸上 |
| 背景图 | 原图 | 浅纸 |
| `ui_bg_color` | `#40F4F4F4`（叠深底） | 浅纸 |
| **结果** | 白字可读 | **白字落在浅纸上，不可读** |

**影响面实测**：`auto_text_tint` 引用 **71** 个文件，`use_theme_color` 引用 35 个。白字是多数派。

### 修法

改按亮暗模式取色，不再按主色亮度推导：

```kotlin
val dark = activity != null && ThemeEngine.isNightMode(activity)
return if (dark) 0xFFE4E1D8.toInt() else 0xFF2C2C2A.toInt()
```

### 风险评估

`autoBackgroundTint`（给控件填主色底）在布局中 **0 处引用**，仅类内与 1 处 Kotlin 调用。
所以不存在"墨色字压在强调色实心块上"的场景，改 autoTint 是安全的。

## 2. 主界面骨架（设计稿三栏）

| 项 | 设计稿 | 改动前 | 改动后 |
|---|---|---|---|
| 左栏 | rail 64px | `wrap_content` | **64dp** |
| 右栏 | side 300px | 25% 百分比 | **25%，上限 300dp** |
| 图标 | 栏内居中 | 仅 start 约束（靠左） | **补 end 约束，居中** |

右栏保留百分比是为了窄屏：2400px 屏 25% = 600px 过宽，加上限后为 300px；小屏仍按比例收缩，不会挤没内容区。

ConstraintLayout **2.2.0**，支持 `app:layout_constraintWidth_max`。
