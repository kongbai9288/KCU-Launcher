# 弹窗观感改造 + 小窗尺寸修复（v0.43.0）

执行者：yuanbao，2026-10-24

---

## 1. 用户反馈

1. 弹窗/填写栏"非常离谱、没有审美"，应当**大**、**有图标示意**
2. 小窗：要么禁用，要么能正常横屏小窗（**倾向后者**）
3. 从小窗回到正常页面会出毛病：布局位置不对、扩大后按钮很小、操作页面偏移、**MC 无法操控**

---

## 2. 追溯：小窗问题的根因

### 2.1 尺寸来源

```
AndroidUtilKt.getScreenWidth()
  → DisplayUtil.screenWidth（-1 未赋值）
  → DisplayUtil.currentDisplayMetrics.widthPixels
       ← refreshDisplayMetrics() ← getDisplayMetrics()
           ├─ 多窗口/PiP → activity.resources.displayMetrics（窗口尺寸）
           └─ 否则      → display.getRealMetrics（屏幕真实尺寸）
```

`JVMActivity extends KCUActivity`，`KCUActivity.onConfigurationChanged` 会调
`DisplayUtil.refreshDisplayMetrics(this)` —— **刷新机制是有的**。

### 2.2 但两处把尺寸"快照"成了不可变值

| 位置 | 代码 | 后果 |
|---|---|---|
| `TouchPad.java:54-55`（原） | `this.screenWidth = AndroidUtilKt.getScreenWidth()`（final 字段） | 构造后不再更新 |
| `MenuView.kt:39-40`（原） | `private val screenWidth = getScreenWidth()`（不可变） | 构造后不再更新 |

**使用点**：

- `TouchPad.java:286-287` 指针 clamp：
  ```java
  targetX = Math.max(0, Math.min(screenWidth, initialX + deltaX));
  ```
  → 小窗构造后切全屏，指针仍被限制在**旧的小窗尺寸内** → **MC 只能操控左上角一小块**

- `TouchPad.java:318` 左半屏判定也用旧值

- `MenuView.kt:97-98` 菜单定位、`173-179` 拖拽 clamp 用旧值 → **布局位置不对**

**这与用户描述的三条症状一一对应。** 是上游固有缺陷，非本项目引入。

### 2.3 修复

| 文件 | 改动 |
|---|---|
| `TouchPad.java` | 删除 final 字段与构造赋值，改为使用时直接调 `AndroidUtilKt.getScreenWidth()` |
| `MenuView.kt` | `private val x = ...` → `private val x get() = ...`（每次访问重新计算） |

`JVMActivity` 已有两层 `OnGlobalLayoutListener` 处理强制分辨率 letterbox，本轮未动。

## 3. 弹窗观感改造

### 3.1 KcuUi 新增

| 方法 | 说明 |
|---|---|
| `iconBadge(ctx, glyph)` | 圆形强调色底 + 白色符号徽章（46dp） |
| `header(ctx, glyph, title)` | 图标徽章 + 大标题横排 |
| `fieldRow(ctx, hint, glyph)` | 前置图标 + 输入区横排 |
| `editOf(row)` | 从输入行取出 EditText |

**图标用字符而非图片资源**：保证风格统一、不新增 drawable、不受设备字体 emoji 化影响
（选用 `↓ # ◇ ≡ !` 等基础符号）。

### 3.2 加大

| 项 | 原 | 改后 |
|---|---|---|
| 卡片内边距 | 16dp | **22dp** |
| 标题字号 | 19sp | **21sp** |
| 输入框内边距 | 12dp | 14dp |
| 输入框最小高度 | — | **46dp** |

### 3.3 顺带修掉两个真实 UI bug

| # | bug | 修法 |
|---|---|---|
| 1 | **年龄页标题与说明重复渲染两遍**（`KcuAgeActivity` 加一次，`KcuAgeGate.buildInto` 又加一次） | 删除 Activity 里的重复 |
| 2 | **RadioButton 未设 id**，`group.check(-1)` 选不中任何项，默认 18 岁在界面上无选中态 | `rb.setId(i + 1)` |

第 1 条正是用户所说"离谱"的直接体现。

## 4. 严格审核

### 4.1 会导致什么错误

| # | 错误 | 处置 |
|---|---|---|
| 1 | TouchPad 删字段后残留引用 | grep 确认 0 处残留 ✅ |
| 2 | MenuView 改 getter 后语义变化 | `val` → `get()` 对外用法不变 ✅ |
| 3 | 每次触摸都调 getScreenWidth 有开销 | 只读一个 int 字段，可忽略 ✅ |
| 4 | `currentDisplayMetrics` 未初始化 | lateinit，KCUActivity.onCreate 已 init ✅ |
| 5 | `fieldRow` 取 child 越界 | 容器固定 2 个子元素 ✅ |
| 6 | 图标字符设备不支持显示豆腐块 | 选用基础符号；**需实机确认** ⚠ |
| 7 | 删重复标题后页面变空 | buildInto 内仍构建标题+说明 ✅ |

### 4.2 对用户使用逻辑的影响

| 导入页 | 图标标题 + 两个带图标输入框 |
