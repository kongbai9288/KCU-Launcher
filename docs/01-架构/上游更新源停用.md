# 上游更新源停用（v0.29.0）

执行者：yuanbao，2026-10-22

---

## 1. 追溯到底

```
UpdateChecker.check()          → 启动时 / 设置页手动
  └─ NetworkUtils.doGet(UPDATE_CHECK_URL_CN | UPDATE_CHECK_URL)
       ├─ https://raw.githubusercontent.com/FCL-Team/FoldCraftLauncher/main/version_map.json
       └─ https://gitee.com/fcl-team/FCL-Repo/raw/main/res/version_map.json
  └─ 解析 ArrayList<RemoteVersion>
  └─ version.getVersionCode() > getCurrentVersionCode(context)
       → showUpdateDialog(context, version)

UpdateDialog
  ├─ 长按确定按钮 → openLink("https://github.com/FCL-Team/FoldCraftLauncher/releases/latest")
  └─ 确定 → FileDownloadTask(getTargetArchUrl())
       └─ url.replace("-all", "-" + arch)
       └─ 缓存落 CACHE_DIR/FoldCraftLauncher.apk → 拉起安装
```

**调用点 5 处**：`UpdateChecker`、`QuarkPromo`、`LauncherSettingPage`、`UpdateDialog`、`MainActivity`。

---

## 2. 发现的问题：会把 FCL 的更新推给 KCU 用户

`getCurrentVersionCode(context)` 取的是**本应用**的 versionCode。KCU 当前为 **28**。

FCL 的版本表里 versionCode 远高于此（官方 1.3.4.0 量级）。判据是：

```java
if (version.getVersionCode() > getCurrentVersionCode(context))
```

**结果：任何 FCL 版本都"比 KCU 新" → 必定弹更新框 → 用户点确定就下载并安装 FCL 的 APK。**

这不是理论风险，是必然发生的行为。同时 `check()` 里还有一句：

```java
versions.stream().max(...).ifPresent(v -> QuarkPromo.updateNetdiskUrl(context, v.getNetdiskUrl()));
```

顺带把 FCL 的夸克网盘推广链接缓存下来。

---

## 3. 为什么不能改成"指向自己的仓库"

考虑过把 URL 换成 KCU 仓库的 `version_map.json`，比对 schema 后放弃：

| RemoteVersion 字段 | KCU version_map 现状 | 结论 |
|---|---|---|
| `type` / `versionCode` / `versionName` / `date` | 一致 | ✅ |
| `description[].text` 期望 **String** | 实际是 **String[]** | ❌ GSON 解析失败 |
| `url` 下载直链 | **无** | ❌ 产物只是 Actions artifacts，没有稳定直链 |
| `netdiskUrl` | **无** | ❌ |

`UpdateDialog` 还会用 `version.getUrl()` 做 `-all → -arm64-v8a` 替换后下载，url 为 null 会直接 NPE。

**结论：现阶段没有自有更新源，联网检查无从谈起。停用是正确的，不是妥协。**

## 4. 改动

| 文件 | 改动 |
|---|---|
| `UpdateChecker.java` | 删 2 个 FCL URL 常量；`check()` 与 `showCurrentChangelog()` 改为不联网的空任务；清 8 个失效 import |
| `UpdateDialog.java` | 长按链接改指 KCU releases；下载缓存文件名 `FoldCraftLauncher.apk` → `KCU-Launcher.apk`；task.setName 同步 |

**保留**：`RemoteVersion`、`ChangelogDialog`、`UpdateDialog` 全部类与 `UpdateChecker.setIgnore/isIgnore/getCurrentVersionCode` —— 将来接自有更新源时直接复用，不必重写。

## 5. 严格审核

### 5.1 会导致什么错误

| # | 错误 | 处置 |
|---|---|---|
| 1 | **未改动前**：必然弹 FCL 更新框并诱导安装 FCL APK | **已停用** |
| 2 | 只删 URL 常量不改方法 → 编译失败（找不到符号） | **方法体一并改** |
| 3 | 改 `check()` 后 `QuarkPromo` 不再被赋值 | `QuarkPromo` 仍在 MainActivity 中有独立逻辑，未删类；是否弹窗取决于其自身判空，属既有行为 |

### 5.2 对用户使用逻辑的影响

| 路径 | 结果 |
|---|---|
| 启动 | 不再请求 FCL 版本表 ✅ |

| 设置 → 查看更新内容 | 同上 |
| 被诱导安装 FCL APK | **已不可能** ✅ |

**已知代价**："检查更新"目前是静默无反馈的空操作。这是**诚实的状态**——没有更新源就是没有，不该拿上游的糊弄。
