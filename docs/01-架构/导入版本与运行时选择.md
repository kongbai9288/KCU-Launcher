# 导入版本与运行时选择（v0.40.0）

执行者：yuanbao，2026-10-23

---

## 1. 需求

用户对之前"导入 jar"的实现不满意，要求：

1. 用户放进去后**显示"未知"**
2. 启动时**让用户自己选 JDK**
3. 下一次使用启动器时**显示具体版本**

---

## 2. 追溯到底

### 2.1 为什么之前导入的版本根本不显示

`DefaultGameRepository` 枚举版本时：

```java
LOG.info("No available json file found, ignoring version " + id);
return Stream.empty();
```

**没有 `<id>.json` 的版本目录被整份忽略。**

之前的实现只写了 `<id>.jar`，所以版本压根不进列表。这就是 v0.35.0 遗留项"导入页只写 jar 不写 json"造成的结果。

**这是"显示未知"的前提 —— 必须先让它进列表。**

### 2.2 最小版本 JSON 是否合法

`Version.validate()` 全文只有一条硬性要求：

```java
if (StringUtils.isBlank(id))
    throw new JsonParseException("Version ID cannot be blank");
```

其余字段全可空。所以 `{"id":"xxx","jar":"xxx"}` 可被解析。

### 2.3 默认 JDK 为什么是错的

`JavaManager.findExactOrNextGreater(version)`：

```java
if (version == null) {
    return getJavaFromVersionName("jre8");
}
```

导入版本没有 `javaVersion` → `version` 为 null → **直接返回 jre8**。

用户不满的正是这个：不是"选错了"，是**根本没让用户选**。

### 2.4 接入点

| 环节 | 位置 |
|---|---|
| 启动入口 | `Versions.launch(context, profile, id, injector)` |
| 版本校验 | `checkVersionForLaunching` 之后 |
| 运行时选择 | 新建 `KcuLaunchGate.prepare` |
| 候选列表 | `JavaManager.getJavaList()`（`@JvmStatic val javaList`，init 时扫 `FCLPath.JAVA_PATH` 下含 `release` 的目录） |
| 保存 | `repository.getVersionSetting(id).setJava(name)` + `saveVersionSetting(id)` |
| 版本目录 | `repository.getVersionRoot(id)`（**返回 File**） |

| 文件 | 改动 |

### 3.1 契约

`<版本目录>/kcu_meta.json`：

```json
{
  "known": false,
  "display": "未知",
  "java": ""
}
```

| 字段 | 说明 |
|---|---|
| `known` | 是否已探测出真实版本 |
| `display` | 展示文本，未探测时为"未知" |
| `java` | 用户选定的运行时名；**空表示未选**，下次启动仍会问 |

### 3.2 只对导入版本生效

`prepare` 第一个判断：

```java
if (!KcuVersionMeta.file(versionDir).isFile()) {
    proceed.run();
    return;
}
```

**正常下载的版本没有这个文件，直接放行**，原有启动路径一行未改。

## 4. 严格审核

### 4.1 会导致什么错误

| # | 错误 | 处置 |
|---|---|---|
| 1 | **`new File(File)`** | **已发生并修复**（见 §5） |
| 2 | 弹窗卡住导致启动不了 | 任何异常都 `proceed.run()` 放行 ✅ |
| 3 | 没有可用 JDK 时弹空窗 | `candidates.isEmpty()` 直接放行 ✅ |
| 4 | 用户不选就一直弹 | 选完写入 meta 的 `java`，下次不再问 ✅ |
| 5 | jar 无 `version.json` | `probeFromJar` 返回 null，`known` 保持 false ✅ |
| 6 | `entry.getSize()` 为 -1 | `new byte[-1]` 抛异常，被 catch ✅ |
| 7 | JsonReader/Writer/ZipFile 泄漏 | 各自 finally 关闭 ✅ |
| 8 | 探测到后覆盖用户已选 JDK | 不会，只改 `known`/`display` ✅ |
| 9 | meta 损坏 | `read` 返回默认值 ✅ |

### 4.2 对用户使用逻辑的影响

| 路径 | 结果 |
|---|---|
| 导入 jar | 生成 `<id>.json` + meta，**版本出现在列表** |
| 首次启动该版本 | 弹运行时选择（jre8/17/21/25 等，取决于设备已装） |
| 选完 | 记入 meta 与 `VersionSetting`，立即继续启动 |
| 再次启动 | **不再弹**，直接启动 |
| jar 内带 `version.json` | 探测成功，`known=true`，`display` 写真实版本 |
| jar 内没有 | 保持"未知" |

## 6. 遗留：显示层未接

**"显示具体版本"当前只写到 `kcu_meta.json` 的 `display` 字段，UI 没有读取它。**

版本列表显示的是 `Version.getId()`（即目录名），要显示真实版本需要改 `VersionListItem` / `VersionUI`，而 `Version` 在全仓有 128 处引用，改显示层影响面大。

**本轮没做，如实标注。** 需要确认你想在哪里看到这个版本（版本卡片？列表副标题？）再动手。
