## 1. API 终点追踪：观感到底由谁决定

```
MainActivity.onCreate
  → ImageUtil.loadInto(binding.background, ThemeEngine.getTheme().getBackground(this))
      → ThemeData.backgroundLt / backgroundDk
          → 【终点】R.drawable.background_light / background_dark（jpg）

  → ThemeEngine.registerEvent(leftMenu) { leftMenu.background = GradientDrawable(getColor()) }

  → 全部 KCUTextView / KCUImageView 的 app:use_theme_color="true"
      → ThemeData.getColor() / getColor2()
          → 【终点】ThemePreference 的默认字段值
```

关键结论：**观感不在各页面布局里，集中在两处**——主题默认色（`ThemePreference`）与背景图。逐页改布局是错的着力点。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `ThemePreference.kt` | color `#3D6B66`、colorDark `#4F8580`、color2 `#2C2C2A`、color2Dark `#E4E1D8` |
| `values/colors.xml` | default_theme_color / ui_bg_color / right_menu_color / primary_text / dialog_background |

| `drawable/background_light.jpg`【替换】 | 揉纸纹理，1600×900 |
| `drawable/background_dark.jpg`【替换】 | 深墨纹理，1600×900 |

配色取自设计稿：paper `#F1EFE8`、ink `#2C2C2A`、accent `#3D6B66`、accentHi `#4F8580`。

### 纹理生成

多倍频值噪声（纸浆不均）+ 像素级细颗粒 + 7 条随机折痕（一侧亮一侧暗）+ 暗角。

生成结果实测：

| 图 | 均值 RGB | 标准差 |
|---|---|---|
| light | 232.7 / 229.7 / 222.7 | 5.6 |
| dark | 29.2 / 29.2 / 27.2 | 5.2 |

## 3. 严格自我审核

### 3.1 会导致什么错误

| # | 错误 | 处置 |
|---|---|---|
| 1 | **`icon_background_color` 被 `mipmap-anydpi-v26/ic_launcher.xml` 引用** —— 改它会连带改 App 图标背景 | **已回滚**为原值 `#FFFFFF` |
| 2 | 左栏原为主色实心块，改透明后图标靠主题色在纸面上显现 | 主色 `#3D6B66` 在浅纸上对比充足 |
| 3 | `ui_bg_color` 带 36% alpha，深色模式下叠在深底上会偏灰 | 可接受，形成毛玻璃层次；非可读性问题 |
| 4 | 老用户已存过主题则不会用新默认值 | KCU 是新包名，DataStore 隔离，首次必走默认值；用户在设置页改过则以用户为准 |
| 5 | 背景图分辨率 1600×900，拉伸铺满可能略糊 | 原图为 jpg，同为拉伸；已用 1600×900 平衡体积与清晰度 |

### 3.2 对今后使用逻辑的干扰

| # | 干扰 | 状态 |
|---|---|---|
| 1 | 主题系统仍可让用户改色，改后即脱离纸面观感 | **预期行为**，不锁定 |
| 2 | `ui_bg_color` 共 8 处引用（含游戏内 MenuView、jar 执行器菜单） | 统一观感，符合目标 |
| 3 | `dialog_background` 7 处引用 | 统一观感 |
| 4 | 深色模式配色为自行推演，设计稿未提供 | 已记录 |
| 5 | **页面结构（三栏比例、卡片布局）未改动** | 下一步 |

### 3.3 模拟用户使用逻辑

| 路径 | 结果 |
|---|---|
| 首次冷启动 | DataStore 空 → 用新默认色 + 新背景图 ✅ |
