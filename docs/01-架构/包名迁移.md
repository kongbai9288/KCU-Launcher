# 包名迁移（v0.9.x）

> 执行者：yuanbao，2026-10-19 → 2026-10-20

---

## 1. 结论：只改 applicationId，不动源码包名

### 1.1 规模证据

GitHub 代码搜索（本仓库）：

```
"com.kongbai.kculauncher"  →  total_count = 1196
```

即**约 1200 个文件**包含该包名。完整重命名源码包（`com/tungsten/fcl` → `com/kcu/launcher`）意味着改动上千个文件。

### 1.2 为什么不全量改

| 项 | 全量改源码包名 | 只改 applicationId |
|---|---|---|
| 改动文件数 | ~1200 | **2 处** |
| APK 包名 | com.kcu.launcher | **com.kcu.launcher（同样达成）** |
| 与官方 FCL 共存 | ✅ | **✅** |
| 可签名 | ✅ | **✅** |
| 编译风险 | 高（漏改一个 import 就崩） | **极低** |
| namespace / R 一致性风险 | 有 | **无** |

**Android 官方支持的做法就是 applicationId 独立于代码包名。** `applicationId` 决定 APK 唯一标识，`namespace` 决定 R 文件包名——两者可以不同。

源码包名 `com.kongbai.kculauncher` 是**内部实现，用户不可见**，改它收益为零。

## 2. 实际改动

文件：`FCL/build.gradle.kts`

| 行 | 改前 | 改后 |
|---|---|---|
| 88 | `applicationId = "com.kongbai.kculauncher"` | `applicationId = "com.kcu.launcher"` |
| 120 | `resValue("string","file_browser_provider","com.kongbai.kculauncher.debug.provider")` | `"com.kcu.launcher.debug.provider"` |

**namespace 保持 `com.kongbai.kculauncher` 不动**（第 35 行）——改它会让 R 文件落到 `com.kcu.launcher.R`，而上千个源码文件的 package 仍是 `com.kongbai.kculauncher`，直接编译失败。

### 2.1 为什么必须同步改 file_browser_provider

它是 debug 变体的 FileProvider authority，**硬编码字符串**，不会随 `${applicationId}` 自动变。不改会导致 debug 包的文件分享失效。

---

## 3. 自动跟随的部分（无需改）

`FCL/src/main/AndroidManifest.xml` 中的 authority 全部使用 `${applicationId}`：

```
android:authorities="${applicationId}.document.provider"        (第 174 行)
android:authorities="${applicationId}.provider"                 (第 184 行)
android:authorities="${applicationId}.crashreporterinitprovider" (第 193 行)
```

改 applicationId 后自动跟随，**不需要动 Manifest**。

### 3.1 但 Manifest 里另有 4 个硬编码类引用（不改）

```
com.kongbai.kculauncher.library.browser.FileBrowserActivity       (第 129 行)
com.kongbai.kculauncher.library.crash.CrashReportActivity         (第 133 行)
com.kongbai.kculauncher.core.download.ProcessService              (第 138 行)
com.kongbai.kculauncher.library.crash.CrashReporterInitProvider   (第 192 行)
```

这些指向 `fclcore` / `fcllibrary` 两个包——它们与 `fcl` 是**并列的独立包**，不是 `com.kongbai.kculauncher` 的子包。因为源码包名整体不动，这些引用保持有效。**保持原样。**

## 4.1 【补充】扫描报告暴露的第二处硬编码（已修）

CI 扫描（Actions run 39282032200）统计：

| 项 | 值 |
|---|---|
| 涉及文件数 | **1143** |
| 出现总次数 | **7672** |
| `com.kongbai.kculauncher.core` | 3809 |
| `com.kongbai.kculauncher.library` | 2358 |
| `com.kongbai.kculauncher` | 1352 |
| `com.kongbai.kculauncher.launcher` | 153 |

扫描抓到我**漏掉的一处**：

```
FCL/src/main/res/values/strings.xml:1555
<string name="file_browser_provider" translatable="false">com.kongbai.kculauncher.provider</string>
```

这是 **main source set 的默认值**（release 变体走它），硬编码、不随 `${applicationId}` 变。改 applicationId 后若不改这里，release 包的文件分享会失效。

**已修**：改为 `com.kcu.launcher.provider`。

> 这正是"先扫描再改动"的价值——凭阅读 build.gradle.kts 只能发现 debug 变体的那一处。

### 4.2 布局 XML 中的自定义 View 全限定名（不改）

扫描显示大量布局引用 `com.kongbai.kculauncher.library.component.view.*`：

```xml
<com.kongbai.kculauncher.library.component.view.KCULinearLayout ...>
<com.kongbai.kculauncher.library.component.view.KCUTextView ...>
<com.kongbai.kculauncher.library.component.view.KCUImageView ...>
```

**这反过来印证了决策正确**：若改 `fcllibrary` 包名而不同步改上百个布局，会直接 `InflateException` 崩溃。源码包名不动，这些全部保持有效。
