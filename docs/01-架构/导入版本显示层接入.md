## 1. 承接

v0.40.0 遗留：探测到的真实版本只写进 `kcu_meta.json` 的 `display`，**UI 没有读取**。

用户要求："放进去以后下面显示未知，启动选完 JDK 后下次显示具体版本"。

本轮把显示层接上。

## 2. 追溯

### 2.1 绑定点

```
VersionListPage.render()
  → VersionListItem(profile, id, libraries, tag, drawable, modCount, pinned)   行 130
  → VersionListAdapter.onBindViewHolder
      binding.title.text    = versionListItem.version       行 69
      binding.subtitle.text = versionListItem.libraries     行 74
      binding.subtitle.text = "%s  Mods:%d"                 行 110（覆盖上一行）
```

**注意：subtitle 在同一方法内被赋值两次，最终生效的是第 110 行。** 只改第 74 行会被覆盖。

### 2.2 主页卡片

`MainUI.refreshSelectedVersion()`：

```java
String version = Profiles.getSelectedVersion();
stageVersion.setText(version == null || version.isEmpty() ? ...none : version);
```

### 2.3 为什么不在 onBind 里读文件

`onBindViewHolder` 每次列表滚动到可见项都会执行。在里面读 json 会造成**滚动时反复 IO**。

`VersionListItem` 只在 `render()` 时构造一次（版本集合变化才重建），**构造时读一次并缓存**是正确的位置。

## 3. 改动

| 文件 | 改动 |
|---|---|
| `VersionListItem.java` | 新增 `displayVersion` 字段 + `resolveDisplayVersion()` + getter |
| `VersionListAdapter.kt` | 两处 subtitle 绑定改用 `displayVersion ?: libraries` |
| `MainUI.java` | 版本卡片优先显示 `display` |

### 3.1 判定

```java
if (!KcuVersionMeta.file(dir).isFile()) return null;   // 无 meta → 走原逻辑
return KcuVersionMeta.read(dir).display;               // 未知 / 真实版本
```

**返回 null 表示"不是导入版本"，沿用原显示。** 正常下载的版本不受任何影响。

### 3.2 展示效果

| 场景 | 列表副标题 | 主页卡片 |
|---|---|---|
| 正常下载的版本 | 组件摘要（原样） | 版本 id（原样） |
| 刚导入、未探测 | **未知** | **未知** |
| 探测成功 | 真实版本（如 1.20.1） | 真实版本 |

标题（`title`）仍显示目录名 id —— **未改**，避免影响排序与搜索筛选（搜索按 id 匹配）。
