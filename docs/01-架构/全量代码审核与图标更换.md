### 【严重-2】`load_order.json` 的 `onFailure=abort` 是假的

```java
// KCULauncher.java:567
KcuNativeOrder.loadInOrder(bridge, config.getWorkingDir());   // 返回值被丢弃
```

`loadInOrder()` 返回 `boolean`，`abortOnFailure` 为 true 时返回 false。
**但调用点没接收返回值** → abort 与 skip 行为完全相同。

**这是 v0.38 我自己记录过的已知缺口**（"要真中止得改 FCLauncher 异常路径"），**至今未修**。

后果：玩家在 json 里写 `"onFailure": "abort"` 期待加载失败就中止，实际会继续启动，可能带着缺失的库跑，崩溃点离真正原因很远。

### 【中-4】选 JDK 对话框按返回键 → 启动静默终止

`KcuLaunchGate.showJavaPicker()`：


### 【中-5】清除标记会清掉年龄声明，页面没提示

### 【低-6】`.so` 同步的"是否需要更新"判据偏弱

```java
private static boolean needsCopy(File src, File dst) {
    return !dst.isFile() || src.length() != dst.length() || src.lastModified() > dst.lastModified();
}
```

只比 **大小 + 修改时间**。如果玩家替换了 .so 但新文件**大小相同且 mtime 更早**（从备份恢复、跨设备拷贝保留时间戳），
→ 判定为"不需要复制" → **旧库继续生效**。

表现为"我明明换了文件怎么还是旧的"，且极难排查。

**修法**：加内容哈希比较。成本小。

---

### 【低-7】`probeFromJar` 的一个边界

```java
byte[] buf = new byte[(int) Math.min(entry.getSize(), 65536)];
```

若 `entry.getSize()` 返回 **-1**（ZIP 条目的 size 未知时可能），
→ `Math.min(-1, 65536)` = -1 → `new byte[-1]` 抛 `NegativeArraySizeException`
→ 被 catch 吞掉返回 null → **版本探测恒失败，显示永远是"未知"**。

用 `ZipFile`（基于文件）时 getSize() 通常可靠，风险低。但 failure mode 是静默的。

# 第二部分：启动器图标

## 5. 原图处理

### 5.1 你说得对，它不是标准 PNG

| 项 | HTTP 声称 | 实际 |
|---|---|---|
| 格式 | `image/png` | **JPEG** |
| 尺寸 | — | 1440×1440 |
| 通道 | — | RGB（**无 alpha**） |

**带棋盘格背景**（透明的可视化表示），必须先去背。

### 5.2 去背方法

没用"去掉白色"这种粗暴阈值 —— 立方体上有浅灰绿色块，会被误伤。

改用：

1. **阈值 mask**：`min(RGB) >= 240 且 饱和度 <= 14` → 判定背景
2. **连通域筛选**：只保留**接触画布边缘**的背景连通域（立方体内部的浅色块不连通，安全保留）
3. **软边过渡**：背景膨胀 3px 得过渡带，按"离白的距离"插值 alpha → **消除白边**
4. **降噪**：剔除 <5000px 的前景碎片（JPEG 伪影，实测有 42 个 1-2px 噪点）

### 5.3 结果校验

| 项 | 值 |
|---|---|
| 背景占比 | 55.96% |
| 主体连通域 | 912428 px（单一块，说明立方体是实心且被背景完全包围） |
| 内容 bbox | (221, 143, 1221, 1290) → 1000×1147 |
| **内容中心** | **(721, 716)** vs 画布中心 (720, 720) → **居中** |
| 左右余量 | 221 / 219（对称） |

**居中是自动验证的** —— 之前 bbox 显示 (104,...) 是被噪声拉偏，降噪后归位。

## 7. ⚠ 一个你要知道的图标隐患

`mipmap-anydpi-v26/ic_launcher.xml`：

```xml
<monochrome android:drawable="@mipmap/ic_launcher_foreground"/>
```

Android 13+ 的**主题图标**模式下，系统取 foreground 的 **alpha 通道**用单色填充。
我们的立方体是**实心**的 → 主题图标会显示成一个**纯色六边形块**，认不出是 KCU。

**三个选项**（我没擅自改）：
1. 另做一张 monochrome 图标（KCU 字母轮廓，镂空）
2. 删掉 monochrome 属性（系统回退）
3. 不管（只有开了主题图标的用户会看到）
