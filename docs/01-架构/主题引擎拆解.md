# 主题引擎拆解（v0.26.0）

执行者：yuanbao，2026-10-22

---

## 1. 追溯到底：主题引擎到底是什么

```
ThemeEngine (object, Kotlin 单例)
  ├─ _theme: MutableStateFlow<ThemeData?>
  ├─ getTheme()            ← 87 个文件调用
  ├─ registerEvent(v, r)   ← 87 个文件调用
  ├─ isNightMode(context)
  ├─ applyColor/Dark/2/2Dark        ← 用户换色
  ├─ applyBackground(lt, dk)        ← 用户换背景图
  ├─ applyFullscreen / setCloseSkinModel / setAnimationSpeed / applyColorAlpha
  └─ applyAndSave*                  ← 换色并持久化

ThemeData (data class)
  ├─ 字段：color / colorDark / color2 / color2Dark / colorAlpha
  │        backgroundLt / backgroundDk / fullscreen / closeSkinModel / animationSpeed
  ├─ 派生：getColor / getColor2 / ltColor / dkColor / autoTint / autoHintTint
  └─ companion：getTheme(context) / migrateFromSharedPreferences / saveTheme

ThemePreference (DataStore "theme.json")
  └─ 持久化：四个颜色 + alpha + 三个功能开关
```

**搜索实测**：`ThemeEngine` 命中 **87** 个文件，`ThemeData` 6 个，`ThemePreference` 3 个，`themeDataStore` 3 个。

### 结论：不能直接删类

87 个文件的 View（FCLTextView / FCLButton / FCLSwitch / FCLSpinner / FCLEditText …）在构造时调 `ThemeEngine.registerEvent`，运行时调 `getTheme()`。删类 → 87 个文件全崩，远超"能修"的范围。

**正确拆法**：保留 API 面（87 个调用点零改动），**抽掉"用户可改"的能力**，让主题恒定纸面。行为上主题引擎已死，代码上不崩。

## 2. 本轮改动

| 文件 | 改动 |
|---|---|
| `ThemeData.kt` | `getTheme` 颜色与背景改为常量；不再迁移旧 SharedPreferences；`saveTheme` 只存功能偏好 |
| `ThemeEngine.kt` | 换色四接口、换背景、alpha 调整共 7 个接口废弃为 no-op |
| `LauncherSettingAdapter.kt` | 删除 7 个设置项（4 个配色 + alpha + 亮暗背景图） |

### 拆掉了什么

| 能力 | 状态 |
|---|---|
| 用户自定义主色 / 深色主色 / 次色 / 深色次色 | **移除** |
| 从背景图取色 | **移除** |
| 自定义亮/暗背景图 | **移除** |
| 派生色 alpha 调节 | **移除** |
| 亮暗模式（跟随系统/强制亮/强制暗） | **保留**（必要） |
| 全屏 / 皮肤模型 / 动画速度 | **保留**（功能偏好，非观感） |
| 视频背景 | 保留（未动） |

### 保留功能偏好的理由

`fullscreen` / `closeSkinModel` / `animationSpeed` 是行为开关，不是观感配色。抽掉会损害功能（用户无法关闭 3D 皮肤模型）。它们仍走 DataStore 持久化，只是不再与颜色混在一起。

## 3. 严格审核

### 3.1 会导致什么错误

| # | 错误 | 处置 |
|---|---|---|
| 1 | **`const val` 不能调 `.toInt()`**（非编译期常量），初版写成 `private const val COLOR = 0xFF3D6B66.toInt()` 必然编译失败 | **已改为普通 `val`** |
| 2 | `getTheme` 不再用 `ImageUtil.load` 读自定义背景，但 `runBlocking` 读 DataStore 保留 | DataStore 首次读可能阻塞主线程 —— 原实现即如此，未恶化 |
| 3 | 删除 `applyBackground` 实现后，`FCLPath.LT/DK_BACKGROUND_PATH` 不再被写；若别处仍读该路径会拿到旧文件或空 | 已确认读路径仅 `ThemeData` 一处，已改 |
| 4 | 设置项删除后，对应 tag 常量与 `case` 分支成为死代码 | enum 未用值不报错；case 不可达不报错 |
| 5 | `LauncherSettingPage` 里 `showColorPicker` / `selectImage` 方法仍在 | 无调用点，为死代码，本轮未删（下轮清） |
| 6 | 未使用的 import（ImageUtil/BitmapDrawable/ConvertUtils/FCLPath/File） | **已移除** |

### 3.2 对用户使用逻辑的影响

| 路径 | 结果 |
|---|---|
| 打开设置 → 主题 | 四个配色项与 alpha 条**已消失** ✅ |
| 打开设置 → 背景 | 亮/暗背景图项**已消失**，视频背景仍在 ✅ |
| 改亮暗模式 | 仍生效，取 background_dark ✅ |
| 关 3D 皮肤模型 | 仍生效 ✅ |
| 调动画速度 | 仍生效 ✅ |
| 曾经改过主题色的老用户 | DataStore 里颜色被忽略，一律纸面 ✅ |
| 自定义过背景图的用户 | 不再生效，改用内置纹理 ✅ |

### 3.3 对未来的影响

| # | 影响 | 评估 |
|---|---|---|
| 1 | 主题色不再可配，纸面观感锁定 | **目标即如此** |
| 2 | 87 个文件仍依赖 ThemeEngine API，未来若要彻底删类需逐个改造 | 已记录，属长期债务 |
| 3 | `ThemePreference` 仍含四个颜色字段但无人使用 | 下轮可精简 data class |
| 4 | `ThemeData` 仍支持 `fullscreen/closeSkinModel/animationSpeed` 变更 | 与观感锁定不冲突 |

### 3.4 对代码逻辑的影响

| # | 影响 | 评估 |
|---|---|---|
| 1 | `applyColor*` 变 no-op 后，`updateTheme` 仅被 fullscreen / skinModel / animationSpeed 三条路径调用 | 刷新范围缩小，性能略优 |
| 2 | `getTheme` 不再读文件，背景直接从 res 构建 | 启动略快，不再依赖存储权限 |
| 3 | `saveTheme` 不再写颜色 | DataStore 写入体积变小 |
| 4 | `registerEvent` 语义不变 | 87 个调用点零影响 ✅ |
