## 1. API 终点追踪

```
MainUI.onCreate
  → findViewById(R.id.announcement_layout)
      → ThemeEngine.registerEvent(...) { background.setTint(theme.getColor()) }
          → 【终点】公告卡底色由运行时 tint 决定，XML 背景被覆盖

  → checkAnnouncement()
      → HttpRequest GET announcement_v2.txt（GitHub raw / Gitee）
      → getJson(Announcement.class) → 填充 title / announcement / date
```

关键发现：**公告卡底色不在 XML 里，在 MainUI 的 registerEvent 里被 tint 成主色。** 只改 XML 无效。

## 3. 严格自我审核

### 3.1 会导致什么错误

| # | 错误 | 处置 |
|---|---|---|
| 1 | **只改 XML 无效** —— 公告卡底色被 MainUI 运行时 tint 成主色覆盖 | **已删除**该 registerEvent |
| 2 | 删除 tint 后 `announcementLayout` 字段仍在使用（registerEvent 之外的引用） | 保留字段声明，仅删 tint 回调 |
| 3 | `ThemeEngine` import 可能不再被使用导致警告 | 仍用于 `isCloseSkinModel()`，保留 |
| 4 | 水印叠在 SkinViewer 上可能被遮挡 | 水印在底部 14dp，SkinViewer 高 80% 居中；需实机确认 |
| 5 | `app_version` 不在 strings.xml，是 resValue 生成 | 已在 MainActivity 中使用，MainUI 引用成立 |
| 6 | 深色模式下 `kcu_line` 若为深色描边会看不见 | night 用 `#1AE4E1D8` 浅描边 |

### 3.2 对今后使用逻辑的干扰

| # | 干扰 | 状态 |
|---|---|---|
| 1 | 去掉 tint 后公告卡不再随主题色变化 | **预期**，纸面观感下卡片应为纸色 |
| 2 | `bg_container_white` 仍被 39 处引用（公告卡已改用新 drawable） | 其余场景统一纸色 |
| 3 | 水印文本依赖 resValue，版本号同步 | 跟随 build.gradle 版本 |
