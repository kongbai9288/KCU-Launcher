## 2. 追溯：这个文案渲染在哪

```
AboutPage.kt:126
  ItemAboutDescBinding.bind(holder.itemView).title.setText(R.string.about_desc)
```

**唯一引用点**。整页关于描述就这一个字符串。

### 顺带查清一件事：`about_launcher` / `about_developer` 是死字符串

| 字符串 | 值 | 源码引用 |
|---|---|---|
| `about_launcher` | `Fold Craft Launcher` | **0** |
| `about_developer` | `FCL-Team` | **0** |

两个都**只出现在 docs / CHANGELOG / version_map 里**，没有任何 Java/Kotlin 引用，
**不会显示在任何界面上**。

这个发现决定了本轮的一个判断：新文案说"kongbai9288 是架构师"，
而 `about_developer` 存着 `FCL-Team` —— **两者不冲突，因为后者根本不显示**。
所以保留它们（v0.49 定的"上游署名保留"），不改。

## 3. 改动

### 3.1 拼写修正（2 处，必须说明）

用户原写 `Flod craft laucher`：

| 原写 | 修正后 |
|---|---|
| `Flod` | **`Fold`**（少一个 r） |
| `laucher` | **`Launcher`**（少一个 n） |

理由：这是**上游项目的正式名称**，且带有法律署名性质。
（与 v0.48 包名案例一致 —— 当时 `kculaucher` 也确认补齐为 `kculauncher`。）

### 3.2 句式

用户原句"由架构师 kongbai9288 **由** fcl 为主体"有两个"由"。
按语义理解为第二个是"**以**"，照此顺句，**核心信息一字未减**：

| 要素 | 保留 |
|---|---|
| KCU Launcher | ✅（统一大小写） |
| 架构师 kongbai9288 | ✅ |
| 以 FCL（即 Fold Craft Launcher）为主体 | ✅ |
| 其他项目为辅 | ✅ |
| 开源、源码可修改 | ✅ |
| GPL | ✅（写明 GPL-v3） |

### 3.3 最终文案

> KCU Launcher 是一个由架构师 kongbai9288 以 FCL（即 Fold Craft Launcher）为主体、其他项目为辅的开源软件，源码可修改，遵循 GPL-v3 许可发布。
>
> 页面下方的条目携带图标，点击「开源许可」可查看所使用开源项目的许可（全部内置于本地，不联网获取）。

第二段是**原文案里已有的 UI 引导**（告诉用户能点开源许可），保留 —— 删了用户不会知道那个入口。

### 3.4 改了哪两个文件

`values/strings.xml`（默认 locale，无对应翻译时都走它）
`values-zh/strings.xml`（中文）

**中文那份原来的内容**是上游的原神风格元叙事，开头写着
「KCU 是由 **FCL-Team** 基于 HMCL 的核心功能…开发」——
**这句在新的署名表述下是错的**（把开发者说成 FCL-Team）。一并替换。

它里面「如果你要传播分发该软件，请遵循 GPL-v3 协议」的法律声明，
由新文案的「遵循 GPL-v3 许可发布」承接，**没有丢**。
